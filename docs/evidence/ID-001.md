# ID-001 — Canonical Editor identity (builder-2)

## Implementation and assumptions

`src/atlas_commander/identity.py` exposes `resolve_editor(observation, mappings,
mapping_version=..., historical=True)`. Mappings are explicit dictionaries keyed
first by version, then by exact Monday person ID. Values are lists/tuples of
EditorIdentity records so conflicting entries cannot disappear through a
last-write-wins dictionary conversion. Callers must preserve all candidates.

The caller supplies an `EditorObservation` extracted from the configured Monday
Editor column. Board, item, column, observation timestamp, source person IDs and,
for historical observations, the establishing event ID are retained as evidence.
This fixture-mode module trusts the caller's extraction and event association;
it does not fetch Monday, verify an event against remote history, or infer which
historical observation belongs to a work cycle. Historical resolution is the
default and rejects current snapshots even when they carry an event ID. An
explicit `historical=False` allows current Editor snapshots only. There is no
assignee argument or fallback.

Missing Editors, multiple distinct person IDs, unmapped IDs, absent mapping
versions, conflicting records and invalid records produce `identity: null` and
an exception code, retaining evidence for quarantine. Identical repeated IDs or
records are idempotent. Any differing mapping records for the same version/person
are ambiguous, including differing display labels. Names are output labels only;
IDs are never coerced, trimmed, case-folded or resolved by name. Mapping versions
must be selected explicitly; there is no latest-version fallback.

Resolution performs no clock reads, random operations or input mutations.
Candidate evidence is sorted so reversing conflicting records produces the same
result. No metrics are calculated in this task; identity provenance accompanies
both accepted and quarantined results for downstream audit.

## Contract impact

No frozen schemas, DAG, fixtures or unrelated modules were changed. Accepted
`identity` objects match `contracts/editor-identity.schema.json` version 1.0.0,
verified by the existing schema validator against the checked-in good fixture.
The surrounding result (`identity`, `exception`, `evidence`) is an internal Python
API, not a persisted exception or common metric-evidence contract. Downstream
integration must adapt it to its own output contract; no schema compatibility
claim is made for that internal envelope.
