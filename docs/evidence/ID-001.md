# ID-001: canonical Editor identity

Implemented `src/atlas_commander/identity.py` and `tests/test_identity.py` in fixture mode.

## Interface and assumptions

`resolve_editor(evidence, mappings, mapping_version)` accepts explicit `EditorEvidence`
and EditorIdentity mapping rows. It indexes the selected rows by the exact mapping
version and Monday person ID. The version is required; there is no latest-version,
name, normalized-string, or current-assignee fallback. Successful output is a fresh
EditorIdentity dictionary. Identical duplicate rows are idempotent; differing rows
for the same person/version are quarantined, including inconsistent display metadata.
Multiple distinct Editor person IDs are ambiguous even if mappings could converge.

Evidence must identify a Monday board, item, Editor column, and historical event.
The caller is responsible for extracting the actual Editor-field value associated
with that event/cycle from Monday; the resolver cannot independently authenticate
caller-supplied provenance in fixture mode. Its interface has no current-assignee
input. A current snapshot without an event cannot establish historical identity.
Person IDs are strings and are not coerced, trimmed, case-folded, or inferred.

Missing, ambiguous, unmapped, invalid, or unevidenced identity raises
`IdentityResolutionError`. Its JSON-serializable `exception_output` retains the
reason code, pinned version, supplied evidence, and sorted candidate canonical IDs.
Callers should route this output to quarantine and exclude the item from metrics.
The resolver itself performs no persistence or external calls. Mapping rows for
other people/versions do not affect the selected identity.

## Evidence and validation

- `fixtures/good/editor-identity.json` resolves exactly to editor-42/person-42 at
  identity-v1 and passes the unchanged EditorIdentity JSON schema.
- `fixtures/bad/missing-editor.json` supplies the board/item context for the
  missing-Editor test; it is rejected with MISSING_EDITOR and retains item evidence.
- Conflicting canonical mappings produce AMBIGUOUS_EDITOR with identical exception
  output under either mapping order. Multiple Editor values are also rejected.
- Tests cover identical duplicates, explicit version selection, unavailable versions,
  renamed display metadata, name/case/whitespace non-matches, invalid mapping rows,
  missing event/board/item/column evidence, non-Monday provenance, invalid person
  values, and output isolation from mapping input.
- `PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_identity.py' -v`:
  **PASS, 13 tests**.
- `make test`: **PASS**; Ruff, mypy (4 source files), 11 commander tests,
  6 contract tests, 2 integration tests, 2 E2E tests, and JSON syntax validation.
  The existing Makefile enumerates suites and does not discover test_identity.py;
  the separate command above is required for this candidate's identity coverage.

## Contract and metric impact

No frozen contracts, task graph, or unrelated modules changed. Successful output
conforms to editor-identity.schema.json version 1.0.0 without additional properties.
EditorEvidence and exception output are local Python interfaces, not new frozen
schemas. Supporting event evidence remains with the caller on success because the
identity contract has no evidence field. This module emits no metric values and
changes no duration, deadline, cohort, quality, revision, or actor rules.
