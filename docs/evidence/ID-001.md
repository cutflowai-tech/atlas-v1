## ID-001 — Resolve canonical Editor identity (builder-3 candidate)

Mode: fixture. Affected contract: `contracts/editor-identity.schema.json` (read-only; not modified).

## Implementation

`src/atlas_commander/identity.py`

- `IdentityMapping.from_dict({"mapping_version", "entries": [{monday_person_id, editor_id, display_name}]})` builds an explicit, versioned mapping keyed by Monday person ID. Missing `mapping_version` or incomplete entries raise at load. A person ID mapped to two different canonical records is recorded in `conflicts`, never silently picked.
- `resolve_editor(observation, mapping)` returns an `IdentityResolution` with either a contract-valid `identity` (validated against `editor-identity.schema.json` before return) or an `exception` record.
- `resolve_editors(observations, mapping)` returns `(resolved, exceptions)` in deterministic order (board, item, code), independent of input order.

Quarantine codes (exception output):

| Code | Trigger |
| --- | --- |
| `MISSING_EDITOR` | No Monday person ID in the Editor column for the work interval |
| `AMBIGUOUS_EDITOR` | More than one distinct Monday person ID |
| `AMBIGUOUS_MAPPING` | Mapping lists conflicting canonical records for the person ID |
| `UNMAPPED_EDITOR` | Person ID absent from the versioned mapping |
| `UNEVIDENCED_EDITOR` | No non-empty Monday `event_ids`; explicit reason when source is `current_assignee` |
| `INVALID_OBSERVATION` | Missing board/item/column ID, unknown source, or non-canonical person ID (bool, whitespace-padded, non-string/int) |

Exception records carry `monday_board_id`, `monday_item_id`, `column_id`, `event_ids`, `source`, `monday_person_ids`, `mapping_version`, `code`, `reason`.

## Rules enforced

- Resolution is by exact Monday person ID only; display names (observed or passed in the ID slot) never resolve identity, and the output `display_name` comes from the mapping.
- A current assignee is accepted as the historical editor only when accompanied by Monday event evidence.
- Integer Monday person IDs (API form) are canonicalized to their decimal string; no other normalization (no case folding, trimming or fuzzy matching).
- `mapping_version` is carried into every identity and exception.

## Assumptions

- Observation input shape (`monday_board_id`, `monday_item_id`, `column_id`, `editor_person_ids`, `source`, `event_ids`) is module-local; the upstream normalizer is expected to supply the Editor column value as of the work interval.
- Sources: `historical_column_value`, `activity_log`, `current_assignee`. All require event evidence.
- Duplicate identical person IDs in one observation collapse to one (not ambiguous).
- Same person ID mapped twice to the same editor with different display names is treated as a mapping conflict.
